# Project Configuration Template

## Overview
This document serves as a template for configuring a small application project. Each section outlines key aspects of the project that need to be defined. Tasks for each section will be created in GitHub for the product manager to fill in and complete. GitHub will serve as the source of truth, with Issues holding all key context and details.

---

## 1. Define the Tech Stack
- **Question**: What technologies will be used to build the application?
  - Frontend (if applicable): Frameworks, libraries, etc.
  - Backend: Programming languages, frameworks, etc.
  - Database: Type of database (SQL, NoSQL, etc.).
  - Other Tools: CI/CD pipelines, testing frameworks, etc.
- **GitHub Task**: Create a task for the product manager to define the tech stack.

---

## 2. Define Integrations
- **Question**: What external tools or systems need to be integrated?
  - Examples: GitHub Issues, Playwright, Woodpecker, Slack, etc.
- **GitHub Task**: Create a task for the product manager to list and describe required integrations.

---

## 3. Define the Primary Objective
- **Question**: What is the primary goal of the application?
  - Example: Automate task management for engineering teams.
- **GitHub Task**: Create a task for the product manager to define the primary objective.

---

## 4. Define the Target Users
- **Question**: Who are the target users of the application?
  - Example: Engineering teams, product managers, QA professionals.
- **GitHub Task**: Create a task for the product manager to define the target users.

---

## 5. Define the Problem the Product Solves
- **Question**: What problem does the application solve for the target users?
  - Example: Streamline task management and improve collaboration.
- **GitHub Task**: Create a task for the product manager to define the problem the product solves.

---

## 6. Define Key Deliverables
- **Question**: What are the key deliverables for the application?
  - Example: Functional backend prototype, integration with GitHub Issues, automated testing workflows.
- **GitHub Task**: Create a task for the product manager to define the key deliverables.

---

## 7. Define Must-Have Features
- **Question**: What are the must-have features for the application?
  - Example: Task ingestion, code generation, automated testing, scheduling.
- **GitHub Task**: Create a task for the product manager to define the must-have features.

---

## GitHub Task Creation
For each section above, create a GitHub Issue with the following details:
- **Title**: [Section Name] - Define [specific aspect].
- **Description**: Include the question(s) and examples provided in this document.
- **Assignee**: Assign to the product manager.
- **Labels**: Add relevant labels (e.g., "Configuration", "Product Definition").
- **Checklist**: Add a checklist for sub-tasks or specific points to address.

---

## GitHub as the Source of Truth
- All project context, requirements, and tasks will be managed through GitHub Issues.
- Each Issue will hold:
  - Key context and details for the task.
  - Links to related Issues or documentation.
  - Updates and comments for tracking progress.
- GitHub will serve as the single source of truth for the project, ensuring transparency and collaboration.

---

## Outcome
A fully configured project with:
- A defined tech stack.
- Clear integrations.
- A well-defined objective, target users, and problem statement.
- Key deliverables and must-have features identified.
